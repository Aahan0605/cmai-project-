# Dataset card: OptLab-TIMIT

An openly licensed real/fake talking-face dataset assembled for this project from two public
datasets, so that Phase 2 can run without the request-only FaceForensics++ / Celeb-DF /
FakeAVCeleb. Nothing here is generated by this project: the fakes come from DeepfakeTIMIT, and
this repository only standardises the files, defines identity-disjoint splits and extracts
features.

## Sources

| | VidTIMIT (real) | DeepfakeTIMIT (fake) |
|---|---|---|
| Host | Zenodo record [158963](https://zenodo.org/records/158963) | Zenodo record [4068245](https://zenodo.org/records/4068245) |
| Licence | CC BY-NC-ND 4.0 | CC BY-NC-ND 4.0 |
| Content | 43 people, 10 spoken sentences each (plus head-rotation clips, unused) | Face swaps for 16 similar-looking pairs of VidTIMIT people (32 subjects × 10 sentences) |
| Video | JPEG frames, 512 × 384, 25 fps | H.264, 512 × 384, 25 fps; two versions: lower quality (64 px swap model) and higher quality (128 px) |
| Audio | 16-bit mono WAV, 32 kHz | The original VidTIMIT audio, unmodified |

Both archives are open access (no request form). The licence allows research, non-commercial
use; *no derivatives* means the standardised clips and feature caches must not be
redistributed. This repository therefore commits only the split manifests (clip IDs, labels,
identities), never videos, frames, faces or features.

**Required citations** for any publication that uses this data:

- P. Korshunov and S. Marcel, *DeepFakes: a New Threat to Face Recognition? Assessment and
  Detection*, arXiv and Idiap Research Report, 2018.
- C. Sanderson and B. C. Lovell, *Multi-Region Probabilistic Histograms for Robust and Scalable
  Identity Inference*, LNCS vol. 5558, pp. 199–208, 2009.

## How it is built

```bash
uv sync --extra extract
optlab fetch-timit                 # download (MD5-checked, resumable) and standardise -> data/timit/
optlab prepare --dataset optlab_timit --root data/timit
optlab extract --dataset optlab_timit_hq --backbone clip_vit_b16 --root data/timit
optlab extract --dataset optlab_timit_hq --backbone wav2vec2_base --root data/timit
optlab extract --dataset optlab_timit_lq --backbone clip_vit_b16 --root data/timit
optlab extract --dataset optlab_timit_lq --backbone wav2vec2_base --root data/timit
```

**Standardisation.** A detector should not be able to tell real from fake by file format. Every
clip, real or fake, ends as H.264 MP4 at 512 × 384 and 25 fps, written by the same encoder
(OpenCV's bundled FFmpeg). Real frames first get one extra H.264 pass. That mirrors the H.264
encode the fakes already went through, so both classes share the history JPEG → H.264 →
H.264. Raw archives are deleted once their clips are written.

**Two datasets, one split.** `optlab_timit_hq` = reals of the 32 swapped people +
higher-quality fakes; `optlab_timit_lq` = the same reals + lower-quality fakes. Both manifests come from a single
identity-disjoint split: a fake shows two people (the person in the video and the face donor),
so each swap pair and its real clips form one group, assigned whole to train, val or test
(70 / 15 / 15 by clip count, seed 0; val is further split into `tune` and `fusion` halves).

## Protocol used in `baseline_timit`

| | Train | Test |
|---|---|---|
| `in_distribution` | HQ fakes + reals, train identities | HQ fakes + reals, held-out identities |
| `cross_dataset` | (same model) | **LQ** fakes + the same held-out reals |

The second protocol tests transfer to a different generator setting (a smaller face-swap
model, with different artefacts) on unseen people. It is a weaker shift than the
FF++ → Celeb-DF transfer the project was designed around, and it is reported as such.

## Known limitations and confounds

- **Residual encoding difference.** The fakes' first H.264 encode used the DeepfakeTIMIT
  authors' settings, which are not published; the reals' first encode used ours.
- **Audio carries no label signal by construction, but only after alignment.** DeepfakeTIMIT's
  README says the original audio was kept, but its WAV files are resampled to 16 kHz while
  VidTIMIT's are 32 kHz. Used as shipped, the two classes differ in resampling artefacts, and
  in the first baseline (`baseline_timit`, superseded) the audio stream alone reached
  validation AUC up to 0.72. `fetch-timit` therefore replaces each fake's WAV with the real
  clip's original (`align_fake_audio`), making the audio byte-identical across classes. It is
  kept as a control stream.
- **Never-swapped people are excluded.** 11 of VidTIMIT's 43 people have no DeepfakeTIMIT
  fakes. Kept in, they are always "real", so anything that identifies them (voice,
  appearance, recording session) predicts the label; in `baseline_timit_v2` (superseded) the
  audio stream reached validation AUC 0.64 that way although audio was identical across
  classes. The manifests therefore keep only the 32 swapped people (`timit.parse(...,
  paired_only=True)`): every person has 10 real and 10 fake clips, and every audio clip
  appears once as real and once as fake.
- **Small.** 32 people, 320 real and 320 fake clips per quality: per-seed variance will be
  large, and few comparisons will be distinguishable.
- **Old and easy fakes.** DeepfakeTIMIT (2018) fakes are lower quality than modern deepfakes,
  so in-distribution AUC may saturate near 1.0, which leaves little room to separate
  optimizers. The LQ transfer test and the convergence metrics then carry most of the signal.
- **Studio recordings.** Every clip is frontal, evenly lit and against the same background.
  Findings may not transfer to in-the-wild video.
- **Real people.** The subjects are identifiable individuals who consented to the original
  VidTIMIT recording; this project only classifies their videos and must not be used to make
  claims about them.
